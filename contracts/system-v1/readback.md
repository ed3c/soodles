### Owner next-action output — ed3c/soodles#21

`landing.py` owns the `next` projection. Every transition response names the
invoked owner, action, phase, classification, and next step. A provider readback
names GET operations against the admitted repository, Issue, PR, head, and run.
It states missing inputs and the resumed operation explicitly. A local input
step names the supervisor, required inputs, known checkpoint, and structured
executable help argv. It never invents a readback path, binary, claim, or authority.
RESOLVED returns action=stop and next=null without rewriting the checkpoint.
These fields are returned projections. They are not another durable state machine.

The existing connector write payload remains exact inside `request`.
Transport must consume only that payload. Dispatch persists its offered intent
before returning it. When the command runs, all existing head, readback, phase,
and write guards still execute. A previously printed next step confers no
execution authority. Prepared delivery requires fresh provider readback.
Unknown offers lead only to owner readback. Awaiting or interrupted reconciliation
names its missing binary input. It does not request indefinite provider polling.

Structured refusals and human diagnostics derive from one invalid field/value
and next action. The invoked CLI verb owns the refusal. A substring of the
invalid field does not select the owner. Explicit transition refusals can name
a different legal recovery operation with one help route. Parser and input
failures are also structured. Old checkpoint schemas retain their existing
interpretation. Displayed next commands never authorize migration or retry.

`delivery_oracle.py` is the nearest standalone CLI and process observer.
It retains existing SIGKILL, concurrent dispatch, and lost-response controls.
It also rejects conflicting next operations and terminal readback output.
Its terminal checkpoint is an explicit fixture, not a live reconciliation claim.
Candidate copies remain non-authorizing. Supervisor-selected external bytes
judge baseline, treatment, and planted regression. Existing base-recovery
consumers read the same structured projection and unchanged nested connector
payload.

N/P/L/R scope follows Noodles' authority classes, not its default-branch
verifier topology. Skill guidance is P. Inventory, prose, and metrics are N.
Tested local transition refusal is L. Actual provider-enforced checks and
readbacks are R for their own claims. This contract does not make owner output
infallible. For a same-atom correction, use pre-offer invalidation. Preserve
unknown writes. Replace incorrect next-command tests with controls that
distinguish valid from invalid behavior. A candidate cannot promote its own
changed judge.

### Cross-repository dependency satisfaction — ed3c/soodles#113, #115

The installed supervisor owns DAG edge selection and carries each exact result
in the immutable landing claim. `dependency_binding.py` validates that list and
projects the producer Issue, PR, merged commit, base branch, merge-to-main
comparison, runtime and jobs as indexed `dependency_N_*` GETs beside the
consumer GETs. Soodles contains no producer/consumer edge registry and exposes
no Agent-facing repository, revision, workflow or dependency policy flag.

Before consumer acceptance, every landing transition validates all selected
results. A complete result proves completed Issue closure, merged PR identity,
ordered parents, exact tree, and successful exact-head runtime. It also proves
that the merged artifact equals current producer main or is its ancestor.
Missing evidence, closure alone, foreign repository, wrong revision, divergent
ancestry, or missing acceptance step causes refusal before checkpoint or provider
write. The refusal returns the same owner route with exact readbacks. Malformed
or duplicate dependency identities cause refusal during claim validation.

Eligibility creates no dependency checkpoint. After all selected results pass,
the existing repository profile and landing state machine remain the only
consumer acceptance and effect owners. A claim without dependencies stays
independent. Landing never infers that omission proves DAG completeness.
The external supervisor/admission owner must supply the complete set.
Route migration preserves the list exactly. Provider fixtures provide L-class
discrimination only. Exact provider Issue, PR, run, and final delivery readbacks
retain their own R-class scope.
