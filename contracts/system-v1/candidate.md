### Atomic candidate delivery — ed3c/soodles#97

One causal Issue atom carries its correction and required evidence through one PR.
Include comparison observers and manifests only when the task selects that measurement.
Candidate heads are immutable attempts. Missing required evidence, byte mismatches
and failed required checks block merge. Correct them on a new head of the same PR.
Do not rerun an unchanged failed head.

Only the terminal complete head can merge after its selected exact-head checks pass.
Test Manager owns test scope and optional quality-report demand.
After merge, consume the existing landing owner's runtime evidence and provider readback.
Merge does not request another runtime run or quality scan.
Do not label a PR result as a main-head execution.
A defect found after merge needs a new Issue and rollback boundary.
That correction cannot be counted as part of the earlier one-PR delivery.

This rule changes no evaluator authority. Frozen external observers judge
candidate behavior. The candidate verifier checks committed byte bindings.
Provider checks and readback establish only their own R-class claims. One PR
may contain P-class source and N-class evidence. Neither class authorizes its
own landing.

Schema 4 extends schema 3 with one externally selected `comparison` requirement.
Schemas 1/2/3 keep their existing meaning. The bounded `pclass_replay_v2`
schema-2 recovery family binds several identities in the Issue contract:
repository, Issue, base, experiment, required target, instruction bytes, and raw,
gates, and manifest digests. Evidence and instruction paths are required paths.
Only the three fixed analyzer paths at the base revision are supported.

The shared candidate discriminator checks exact Git bytes and actual raw
instruction observations. It then runs the pinned replayer in a bounded,
credential-free disposable process. It retains the raw result. Through the
candidate receipt, it binds admission to the final head and tree. Committed
evidence need not name its own future commit. Nonregression cannot meet an
improvement requirement.

Before push and PR creation, local publication rechecks the fresh Issue.
Local landing preserves the validated Issue contract through start, advance,
and dispatch, including fresh effect readbacks. Unsupported gated cloud delivery
refuses with supervisor-owned `supported_local_comparison_delivery`. Workflow
success cannot replace local comparison custody. Comparison refusals offer no
provider request. They name the missing supervisor input with current
candidate-verify help. These receipts never authorize landing.
Issue #152 exercises this gate with frozen synthetic controls and one external
fresh comparison. Its own schema-3 delivery retains the preselected older
external landing owner. It makes no live schema-4 R-class claim.

`eval.report` owns the versioned feature-map consumer-report boundary.
Before import, the supervisor pins the external selector and fixed evaluator
bytes. Only complete identity-matched evidence receives behavior PASS/FAIL.
Missing observations are INCONCLUSIVE. Invalid bindings are INVALID. Both have
null behavior and a supervisor-owned missing input. Explicit empty operation
reports retain consumer-report scope. This read-only receipt never authorizes
landing. Archived evaluators and existing recovery replay retain their own scope.

### Local accepted-candidate publication — ed3c/soodles#128

Noodle owns the local order, terminal typed outcome, and linked-worktree custody.
Its schema-1 publication claim binds the exact order, stage, attempt, session
evidence, repository remote, branch, base, candidate HEAD, and tree. The claim
authorizes no provider write. Native publication readiness binds the same clean
candidate HEAD and tree, subject, actual host platform, selected executable
digest, and successful native CLI capability checks. It is non-authorizing.
It is not Linux runtime-lock acceptance. Legacy canonical receipts remain accepted.
Schema-2 native readiness runs no regression suite. Test Manager owns behavior
coverage in exact-head Actions. `candidate_publication.NATIVE_TESTS` remains
only for validation of historical schema-1 receipts. Linux exact-head canonical
acceptance runs after PR publication and is required before landing. Its runtime
lock and workflow remain unchanged.

`candidate-publish` consumes only those two current receipts. It rechecks
their evidence bytes and clean Git identity. It reads the current provider
repository, Issue contract, and base. It then derives `soodles/issue-N-HEAD12`
and the exact one-line `Refs OWNER/REPOSITORY#N` body. If the branch is absent,
the owner pushes it with an absent-ref lease and reads it back. If the branch
is equal, the owner reuses it. Every other ref causes refusal. The owner creates
or adopts one exact open PR and reads it back.

A lost or failed push/create response is never replay authority. The owner
performs fresh branch/PR readback once and adopts only the exact intended
effect; otherwise it returns the provider readback prerequisite and stops.
The receipt terminates at PR identity with `authorizes_landing=false`; merge,
Issue closure, landing checkpoints and Noodle cleanup remain with their
existing owners.

The publisher-derived `publication_branch` is distinct from the Noodle local
`worktree` identity. When present, landing accepts only the exact
`soodles/issue-N-HEAD12` derivation, validates provider head/ref against it and
retains the original local worktree for envelope validation and cleanup.

After amendment branch readback confirms the new head, the same exact open PR
may still name the old head. In that case, the atom may supply a bounded
read-only refresh callback. The callback never calls publication again.
Foreign identity and unknown branch outcomes cause refusal. After the single
refresh, the publisher rechecks its original exact PR predicate. Without atom
repair lineage, standalone publication keeps its existing refusal.
`system-context entry soodles candidate publish` selects this consumer's committed
P requirements. It grants no write or landing authority.

For an initialized new lineage, first publication can refresh the same PR
detail once. This requires the branch and PR list to confirm the candidate
while detail still names its known base head. The callback is GET-only.
It reserves durable intent before transport. Changed identity and unknown writes
still require owner readback. Independent successor authorizations have no
automatic repair budget.

## Push receipts and continuation

Before process start, the lifecycle checkpoint retains a push record.
It replaces that attempt with its completed, timed-out, interrupted, or
not-started result. The record binds exact argv, worktree, single ref/lease,
elapsed time, exit status, and credential-redacted stdout/stderr.
The invocation uses installation credentials over the validated repository's
HTTPS endpoint, even if the selected origin uses SSH. Global remote configuration
is unchanged. Credential helpers and askpass fallback are disabled for this
invocation. Workflow-writing admissions request workflows write capability from
the existing registered supplier. Missing capability is its owner's input.
It never permits fallback to another credential.

Exact provider branch and PR readback still decides success. That includes a
lost process response whose effect later becomes visible. Exit zero alone does
not prove publication. A known rejected offer requires completed nonzero Git
porcelain output with exactly one matching ref marked `[rejected]` or
`[remote rejected]`. Do not classify retryability from free-form stderr.
After correcting that named provider capability, the supervisor may re-enter
the same atom command once. The owner rechecks all publication inputs and
preserves the original lease and PR. The same offer permits at most two push
processes. The owner never retries inside the foreground wait loop.
Re-entry after material correction is the supervisor's P-class obligation.
The receipt, exact identity, and limit define the executable bound.

A timeout, incomplete status, missing legacy receipt, or crash remains unknown.
On re-entry, the owner can adopt fresh exact effect readback but cannot reoffer.
Do not create a new authorization to reset the offer. The existing #205 attempt
has no saved process result. It is not retroactively classified as rejected.
Standalone candidate-publish retains a locked external journal beside its
readiness receipt and continues by readback only. These receipts grant no
landing authority.

### Generic target 的 acceptance 身分

Generic readiness 保留 supervisor-selected `target_binding` reference。
Publication 消費原 Noodle claim 的 worktree，不要求 target 安裝 Soodles。
Owner 核對 target origin、base、candidate manifest 與 fresh Issue 後，才可 offer push 或 PR create。
CI 選擇器核對 binding 的全部 jobs 與必要 steps。每個 job 都必須符合 run attempt 與 head。
Correction 使用固定 `base_ref`，不從 provider default branch 推導新的 base。
Binding 缺失、digest 改變或 provider evidence 不完整時，停止相依 effect。
Unknown write 保留原 checkpoint 並要求 owner readback。Readiness 與 fixture 不授予 landing authority。
