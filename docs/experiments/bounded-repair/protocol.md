# Bounded schema-driven repair: fixed delivery obligations

Selected by the external supervisor before implementation on 2026-10-01. This is a product implementation, not an Agent behavior/efficiency comparison. No new evals or model consumers are required. The runtime remains owned by issue-atom/Noodle/publication/landing; this protocol grants no provider authority.

## One causal change
Replace model-inferred recovery with a finite pinned data policy consumed at actual lifecycle boundaries. Route entry -> exact consuming function/decision -> necessary P-class AND closure without asking an Agent to select files. Policy data cannot contain shell templates, arbitrary predicates or callable imports. Reuse the owner checkpoint and locks; do not create another scheduler, retry engine or ledger.

## Required behavior
1. A real runtime path reads the immutable policy and persists its identity, budget and durable repair history in the existing atom checkpoint. No mock booleans from user JSON can prove binding, completion, process exit or cleanup.
2. Detect and classify named existing observations: missing input/prerequisite; identity conflict; stale evidence; invalid/unknown entry or option; unknown effect; actual failed process/owner outcome; cleanup residue; all prerequisites satisfied but no legal next step. Unknown signals stop. Deadlock is a defined invariant, not elapsed waiting. Report missing fact, producer, classification, safe action, remaining budget and stop/wake condition. Do not classify every refusal as a code defect.
3. Integrate at least one actual safe correction at the lifecycle/publication readback boundary and disposable projection reconstruction from unchanged valid source. Stale PR readback after a confirmed push is a useful instance. Read-only continuation must never call push/create/merge/close again. Never declare delivery from a projection. Preserve exact owner next and normal waiting paths.
4. The finite policy contains signal/action/producer/consumer/context references, allowed actions, protected invariants and numeric limits. Validate the table before effects; unknown, cyclic, dangling, conflicting or unsupported records refuse. Necessary P-class is defined per concrete consumer decision, not guessed from phase. CLI verifies committed source refs/digests and expands the AND closure once, preserves existing file-root CLI compatibility, and rejects missing prerequisites/unknown entries. The intended entry selection shape is `./system-context entry issue-atom run`, with the corresponding publication/readback entries if used.
5. Preserve supervisor-fixed subject, required evidence, selected verifier, policy/limits and unknown-write guards throughout repair. A changed candidate policy or deleted evidence cannot certify the running repair. Policy can be proposed for future admission, never promoted into its own active authority.
6. Shared limits: at most one readback refresh, one deterministic repair, one model candidate, one corresponding verification; hard overall action/time bounds. Budget belongs to whole atom/defect lineage, not head or process. Persist intent and reserve before side effects under existing lock. Unknown action outcome remains charged. Duplicate/repeated failure cannot reoffer. Missing counters/lineage/time integrity must stop that repair branch instead of resetting. Existing legacy states may remain operable without automatic repair; missing history must not be auto-upgraded to zero. For same-PR re-admission without trusted prior lineage, automatic repair is unavailable.
7. Readback and rebuild are executable bounded operations. Code/dependency repair must use an enforceably bounded isolated patch-only carrier, with context/output/deadline limits, protected paths and a reserved verification slot. This repository currently has no proven such model carrier: emit typed `bounded_patch_capability_required` with zero model launches, and document that capability gap. Do not build a new agent service or use an unrestricted Codex session as one bounded inference.
8. Confirmation rechecks the original predicate plus unchanged independent invariants. Schema validity alone is insufficient. Once a repair failed, identical failure on a changed head still stops. Waiting for external material change costs no additional model call. Normal owner may resume on valid new data even when automatic repair is exhausted.
9. Verify through the actual code/CLI/process/checkpoint seam, not only a pure decision fixture. Preserve a valid non-case, stale->fresh repair, repeated/unknown effect with zero duplicate writes, restarted budget, tampered protected conditions, and unavailable model capability. Use the nearest existing tests and small raw receipts; no new test matrix or eval gate.
10. Existing exact-head Linux Actions acceptance and independently pinned external landing owner still govern delivery. One Issue/one PR; do not rerun unchanged failed candidate heads. Do not modify Noodle, credentials, runtime lock or workflow. No claim of universal repair, fixed monetary cost, hidden context loading or Agent behavior improvement.
