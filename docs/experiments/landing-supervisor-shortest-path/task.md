# Landing supervisor shortest path — bounded atom

Question: can one terminal candidate reach the existing landing owner without an
Agent selecting publisher bytes, constructing a landing claim/checkpoint, or
guessing the first landing verb?

Observed baseline context is already nonzero at the instruction/capability
boundary: prior fresh cloud delivery consumers searched for an external
publisher/help entry or stopped because publisher/checkpoint material was not
available. This atom does not relabel those historical runs as a new matched
model experiment.

Treatment:

1. the supervisor supplies one fresh raw provider snapshot, one immutable
   publisher descriptor and one Cloud/Local route descriptor;
2. `landing-supervisor` validates `landing identity` on those selected bytes;
3. repository/Issue/PR/head/tree/base/run/worktree are derived only from the
   provider snapshot;
4. a new external claim/checkpoint package is created;
5. the selected publisher's existing `landing start` is invoked exactly once;
6. the returned current owner `next` is the only continuation exposed to the
   consumer.

Cloud is the legal no-local-identity case. Local requires supervisor-supplied
`control_root` and exact `execution_envelope`; neither is discovered.

The observer/tests must reject stale runtime identity, wrong publisher digest,
candidate self-selection and output overwrite before checkpoint creation.

No provider write, merge, close, new Issue, next-task selection, Noodle lifecycle
change or generic retry is part of this atom. CLI closure is L-class local
evidence; AGENTS guidance is P-class and grants no landing authority.
