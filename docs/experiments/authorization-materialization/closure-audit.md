# Authorization shortest-path atom: closure audit

This atom addressed one transition. The authorized local supervisor supplied selected inputs. The producer validated the initial authorization and returned one executable Issue-atom continuation. It does not remove the independent publisher, invent credentials/identity, replace Noodle, add a scheduler or authorize a writer to select its own judge.

## Which paths must be executable

| Decision boundary | Existing/final owning path | What must not remain prompt guesswork |
| --- | --- | --- |
| First local authorization | `supervisor-admission authorize` (this atom) | derive exact Git root/base, config/instruction digests; preserve selected carrier/publisher; emit argv + environment |
| Resume after selection | existing `issue-atom run` | retain exact authorization, refresh owner state, consume typed next; missing selected bytes are not a new task |
| Readiness and evidence | existing admission/readiness and contract controls | reject missing paths, byte mismatch, wrong candidate or unsupported comparison; never silently weaken required evidence |
| Provider unknown outcome | existing landing/readback owner | require current readback before another effect; distinguish refusal from a bounded wait |
| Delivery completion | existing acceptance/landing/reconciliation | exact-head check, provider truth, local reconciliation and terminal receipt; model prose cannot assert completion |
| Feature verification selection | existing feature map and recipe | map commitment → owner → entry/fault → oracle → raw evidence; run only the required relevant checks |

P-class should name the entry, applicability, invariant and how to consume its result. It should not embed a brittle sequence of phase commands, reconstruct argv, or memorize historical paths. The CLI owns state-dependent transitions. Selection of repository, task scope, external judge and actual host capability remains explicit supervisor work.

## Local and global closure

Local closure targets correct completion of one bounded transition with fewer captured avoidable operations, preserving legal cases and hard refusals. The cost target is not a string with fewer CLI calls: a single handwritten program that moves authority or hides extra decisions is not a shorter safe path.

Global closure connected the products of the same atom. A fixed requirement led to executable counterexamples and fresh behavior traces. Independent readback and confirmation then bound the exact source and evidence package to existing Issue/PR acceptance and terminal delivery. A reusable counterexample and feature recipe survive session context; the next fresh session receives exact source/owner/evidence references, not an optimistic prose summary. There is no claim that one atom proves all future tasks or all carriers nondegrading.

The regression gates cover exact identity and source, no observed forbidden effect, selected publisher pins, correct refusal, and authorization validity. Only after those gates do captured operation counts matter. The actual model, hidden reasoning tokens, full transcript and unobserved network/kernel effects remain unknown. This experiment uses native fresh subagents with local fixture access; its results do not stand in for local Noodle/Codex CLI consumer behavior.

## Findings before delivery

1. Initial authorization had no fixed materializer; Session had to hand-build derived authorization fields or incorrectly send the preparation task back to the user. The current baseline already clarified that the authorized Session can act as supervisor. This atom supplies the missing executable operation.
2. First P+CLI prototype passed 28 independent deterministic controls but its prompt invoked a non-executable wrapper directly. A real fresh consumer failed and recovered through Python. Round 1 is rejected and retained.
3. The Python-entry correction produced valid train authorizations in six captured operations per case versus nine for each baseline case. Consumers still guessed an unnecessary internal `schema` field once. These are bounded intermediate observations, not final adoption.
4. Independent source review found that a Git subdirectory passed the old validator but produced a nonexistent continuation entry. This missing discriminator is pinned independently before correction; the original oracle is retained.

Final acceptance, confirmation and delivery status must be read from the accompanying decision and owner receipts, not inferred from this design narrative.

## Cost boundary

Recorded consumer operations are a direct but narrow decision-barrier proxy. They exclude hidden reasoning, nested subprocess operations, and the up-front engineering/evaluation cost. The observed training reductions do not establish lower total lifetime cost. Reuse the deterministic controls and relevant feature recipe, avoid full-map maintenance on each Issue, and use independent fresh comparisons when a behavior claim changes. Canonical acceptance remains once per final clean candidate head on its supported runner. No numerical amortization claim is made without repeated production observations and measured evaluation cost.
