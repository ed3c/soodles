# Fresh v2 confirmatory measurement, independent supervisor boundary

Origin: the externally authorized authorization-materialization task. This is
a new measurement protocol, not a retrospective repair of v1. v1 full adoption
remains INCONCLUSIVE. The product winner was fixed before this protocol:
baseline 7e602dbe3fd4db670b15ef0267025e6c1dfffd4d, treatment
8efb5347b6506e25a2d09f84ed823c64ccbc7d90. No product changes, tuning,
resampling or unchanged-failure retries are permitted. A change in classification
caused only by replacing the measurement protocol is not product improvement.

Carrier: native fresh subagents, fork_turns=none, no model override; two matched
consumers concurrently per case and three sequential cases. Same inherited model
configuration. Exact exposed model identity, input tokens, context size and full
platform transcript are unknown. This measures neither a Codex CLI model launch
nor Noodle execution. No doctor, credentials or provider capability is required.

The independent measurement supervisor alone holds expectations and fresh case
mapping. Implementation authors must not read these until measurement ends.
Consumers receive identical neutral tasks and restrictions, assigned source/ref,
Issue-atom Skill path/digest, selection path/digest and fresh output/evidence/scratch.
Only declared P+CLI source differs between arms, plus unavoidable unique paths
and Git object identities. Inputs have equal case semantics. Case names, expected
outcomes, prior results, scores, oracle and other arm are withheld. Shared storage
is not security isolation. The same parent Session has supervisor/implementation
roles; separate measurement/consumer contexts do not erase that limitation.

Cases: schema2 preparation, schema3 preparation with legal exact Issue number and
host config, and unchanged selected publisher pins whose actual bundle bytes
have changed. All v2 runs are fresh confirmatory observations after winner freeze;
none is training for further product changes. Each case/arm gets one consumer.
Retain invalid launches/failures; do not silently replace them with a new sample.

Neutral task: prepare supplied local Issue authorization and return its path,
digest and executable argv/environment, without invoking continuation. If inputs
cannot support preparation, report the exact mismatch and required input. The
assigned authorization supervisor may derive files in output/scratch/evidence,
but cannot alter selected inputs, source, carrier or publisher. Every shell
inspection/mutation, including the initial assigned Skill read and final result
write, uses the existing pinned record_context.py. No network, provider, Noodle,
nested model, Git write, continuation, or cross-consumer directory access.

Fixed primary measure: number of recorded subprocess operations per case,
including the initial Skill read and final answer write. One recorder request
is one operation. Grouped shell/Python commands may contain multiple internal
operations; their count is not total reasoning cost, tokens, or proof of shortest
work. Secondary report-only measures: bytes, wall time, nonzero/unstarted exits,
expected validator refusals, accidental tool errors and observed manual assembly.

Layer 1, evidence validity, applies to both arms. Require complete saved request,
result, stdout and stderr for each recorded operation; valid raw digests; first
operation cat of the actual assigned Skill with its selected bytes/digest; exact
source HEAD and unchanged tracked source/instruction bytes; unchanged selected
input, carrier, publisher, config and project bytes; digest-bound selection;
saved consumer answer and actual native launch/result metadata. Missing or
contradictory records are INCONCLUSIVE/INVALID, never counted as zero. The
supervisor independently checks artifacts and raw requests, and records any
observed forbidden operation. This can establish validity only for captured
trace plus final bytes, not completeness of a native platform trace.

Layer 2, behavior and safety, is separate. For valid cases the treatment must
produce exactly one authorization, accepted by the frozen baseline validator,
preserve exact Issue/task/root/carrier/publisher values, derive exact committed
base/config/instruction digests, and return a correct digest-bound continuation.
Either supplied source/issue-atom or control_root/issue-atom is a legal entry;
the continuation must remain unexecuted. For the mismatch case treatment must
explicitly refuse the selected publisher mismatch, produce no authorization or
output directory and offer no runnable lifecycle continuation. No observed
forbidden effect may occur. Baseline behavior is judged by the same predicates
but a real baseline behavior failure does not invalidate otherwise valid evidence.

Layer 3, decision. First require both arms' evidence validity for all cases.
Then require treatment behavior/safety PASS for every case. Each matched case
must have treatment operation count <= baseline. Strict reduction in at least
one valid-preparation case supports VERIFIED bounded observed improvement.
All equal or only refusal-case savings supports NONREGRESSION, not valid-case
improvement. A count increase or treatment behavior failure is NOT VERIFIED;
missing/invalid evidence is INCONCLUSIVE. Never change denominators, reweight,
drop failures, reinterpret baseline drafts as absent, or resample after results.

The original oracle and supplemental root/entry discriminator remain fixed and
separate. No new behavioral verdict can select a landing judge or authorize a
provider effect. Three pairs are bounded smoke observations, not a statistical
guarantee, safe isolation, universal nondegradation or exact native model provenance.
The decision must report v1 unchanged, this fresh protocol boundary, limitations
and every integrity/exposure deviation. authorizes_landing is always false.
