# Hypothesis: missing pre-selection routing at Session entry

The root Session table omits the explicitly authorized Local Session before initial authorization selection. Its only local row begins with an admitted Noodle child and directs readers to bounded execution. This gap can send the Local Session into discovery of downstream admission requirements or make it ask the user for an authorization path/SHA that the existing supervisor producer can prepare. The issue-atom skill and local-supervisor-admission recipe already distinguish initial preparation from recovery of a selected authorization; the proposed correction exposes that existing distinction at entry.

The sole change is one row linking directly to the existing issue-atom skill. All original text, including cloud routing and the local child route, is preserved byte-for-byte. There are no CLI, state, product, credential, or authority changes.

Prediction: comparable fresh consumers with explicit local execution authorization and sufficient selected inputs will reach the existing authorize entry with fewer completed command events, avoiding unrelated prepare-help and source discovery and avoiding a request for user-prepared authorization files/hashes. Consumers with an already selected authorization will retain it, and missing selected files or credentials will still require their exact owner inputs. The task’s stopping boundary continues to govern whether the returned continuation is only handed off or executed.

Evidence is limited. The supplied training trace shows discovery through the child recipe, prepare help and admission source before authorize. Train notes report 20 completed command events, but describe task stopping ambiguity, carrier environment contamination and corrected observer defects; that run is not a comparable cost baseline. The selection summary reports valid passing fresh baseline A counts of 11, 13 and 12 (median 12), B 9 and C 10. Those summaries do not supply case details or establish treatment behavior.

Evaluation must first establish valid, correct owner decisions in comparable fresh cases, including initial preparation, missing selected authorization and credential refusal. Only then compare completed command events against the supplied baseline under matching conditions. No candidate evaluation was performed here, and no improvement is claimed. Soodles was not executed.

Possible failure: the additional row may be ignored, add reading cost without reducing commands, or be overgeneralized into replacing selected authority or letting a candidate choose its verifier. The row therefore explicitly confines preparation to initial selection under existing local authorization and preserves owner refusals and candidate boundaries. Any incorrect owner decision rejects the candidate regardless of command savings. Cloud routing, lifecycle continuation, independent landing ownership and existing CLI validation remain unchanged.
