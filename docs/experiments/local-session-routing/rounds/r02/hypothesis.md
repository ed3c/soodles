# Single causal hypothesis

Local Sessions spend unnecessary command events resolving the admission entry's interpreter, verb and authorization state. Putting the existing argv forms and state distinction at root should let an explicitly authorized Session reach the correct owner directly, without asking the user to create an authorization path/SHA that the existing producer derives.

The change starts from the supplied original AGENTS.md. It adds one local route and a compact entry guide; all original text, including cloud routing, remains byte-for-byte intact. The mechanism differs from the rejected round-1 link-only design: the root now exposes Python versus shell invocation, authorize versus lifecycle-owned prepare, and initial preparation versus exact selected-authorization recovery. The skill and recipe remain the source of the selection schema and owner obligations.

The supplied train trace records entry inspection, admission help, prepare help and implementation inspection before authorize (items 8–12), followed by successful preparation. This supports the ambiguity hypothesis, not a causal improvement claim. Train notes explain that this capture had an ambiguous stop point and inherited carrier-context contamination; it is discovery evidence only, not a comparable cost baseline. The candidate explicitly preserves task-specific stopping and does not modify runtime context or CLI behavior.

Prediction: in comparable fresh cases with complete initial selection inputs, fewer completed command events will be spent discovering entry syntax or the prepare branch, while the same validated preparation receipt and exact continuation are retained. Selected-but-missing authorization must still go to its exact owner; missing credential prerequisites must still refuse without a replacement route. Required gates, raw receipts, environment bindings and unknown-write readback remain mandatory. No command batching or suppressed evidence is part of the mechanism.

Possible failure: the extra root guidance may add reading cost without removing discovery, or a consumer may confuse initial selection with recovery, misapply an interpreter, or follow next past a preparation-only stop. Those are correctness failures before costs count. The templates use current-fact placeholders, never fixture identities, paths, expected outputs or credentials. The candidate is P-class guidance only: it grants no new authority and changes no product code, cloud route, owner, CLI state or acceptance gate.
